# DSA4213 Assignment 1 — Language Models, Embeddings, and Representations

Word-level language models trained from scratch on IMDb reviews (Kneser–Ney n-gram, RNN, LSTM,
Transformer), an input-embedding ablation on the LSTM (random-trainable vs own word2vec vs GloVe,
both frozen), and downstream sentiment classification with frozen LM representations.

Index of every table and figure: [results/SUMMARY.md](results/SUMMARY.md); figure captions:
[results/figures/CAPTIONS.md](results/figures/CAPTIONS.md). Working documents: the specification
[docs/TASK.md](docs/TASK.md), the plan [docs/PLAN.md](docs/PLAN.md) and the decision log
[docs/NOTES.md](docs/NOTES.md). Every number in `results/` is produced by the code in `src/` from the
configs in `configs/`; nothing is entered by hand.

## 1. Data access

The IMDb Large Movie Review Dataset (Maas et al., 2011) is downloaded from the Hugging Face Hub
(`stanfordnlp/imdb`: `train` 25,000, `test` 25,000, `unsupervised` 50,000 reviews) by
`scripts/prepare_data.sh`; it is cached under `data/hf_cache/` and is **not** redistributed here.
Manual download:

```bash
python -c "from datasets import load_dataset; load_dataset('stanfordnlp/imdb', cache_dir='data/hf_cache')"
```

GloVe 6B 300d (Wikipedia 2014 + Gigaword 5, uncased; Pennington, Socher & Manning, 2014):

```bash
mkdir -p data/glove && curl -L -o data/glove/glove.6B.zip https://nlp.stanford.edu/data/glove.6B.zip
```

(862 MB; redirects to `downloads.cs.stanford.edu`. `src/glove.py` reads `glove.6B.300d.txt` directly
from the zip.) `data/`, `checkpoints/` and all embedding/GloVe files are git-ignored.

## 2. Preprocessing (exactly as implemented in `src/tokenize.py`, `src/data.py`, `src/vocab.py`)

1. **Cleaning**, in this order: `<br />`, `<br/>`, `<br>` → space; `html.unescape`; character
   normalisation (C1 controls U+0080–U+009F re-interpreted as Windows-1252, e.g. `\x96` → `-`,
   `\x97` → `--`, `\x85` → `...`, `\x91 \x92` → `'`, `\x93 \x94` → `"`; curly/angle quotes, prime,
   back-tick and the standalone acute accent → `'`; curly/low double quotes and the standalone
   diaeresis → `"`; Unicode hyphens/en dash → `-`, em dash → `--`, ellipsis → `...`; remaining
   control and zero-width characters removed); lowercase; whitespace collapsed. Other HTML tags
   are left alone (0.023 % of reviews contain one).
2. **Tokenisation** (deterministic regex, PTB/GloVe style): clitics split first (`don't → do n't`,
   `it's → it 's`, likewise `'re 've 'll 'd 'm`; `can't → ca n't`); then, in priority order, clitic
   tokens, dotted acronyms (`h.p.`, `u.s.`, `e.g.`), the titles `mr. mrs. ms. dr. jr. sr. st. vs.`,
   numbers with internal separators (`3.5`, `10,000`, `8/10`), Unicode-aware words with internal
   hyphens/apostrophes (`well-made`, `o'clock`, `café`), `...`, `--`, and any other single
   non-space character. 14 edge cases are pinned in `tests/test_tokenize.py`.
3. **De-duplication** by cleaned text: 641 unsupervised reviews that also occur in labelled
   train/test and 474 within-unsupervised duplicates are removed (48,885 kept); the 123 texts shared
   between labelled train and test are only reported. Labelled splits are unchanged.
4. **LM splits** (by review, seed 0): 2,000 LM-val, 2,000 LM-test, 44,885 LM-train
   (12,132,567 review tokens).
5. **Vocabulary** from LM-train only: the 25,000 most frequent tokens (ties alphabetical) plus
   `<pad>`=0, `<unk>`=1, `<eos>`=2 → |V| = 25,003 (`results/part1/vocab.tsv`). Token-level `<unk>`
   rates: LM-train 2.01 %, LM-val 2.20 %, LM-test 2.19 %, IMDb-train 2.42 %, IMDb-test 2.42 %.
6. **Streams**: `<eos>`, then each review followed by `<eos>`, as `int32` arrays in
   `data/streams/`; IMDb train/test are stored per review for Part III.

All statistics are in `results/part1/data_stats.json` (including a character census before/after
cleaning); five raw-vs-tokenised examples are in `results/part1/tokenisation_examples.md`.

## 4. Reproducing everything

All commands run from the repository root with the `dsa4213` environment active. Every run is
driven by one YAML in `configs/` (generated by `scripts/make_configs.py`); the exact commands are
in the four shell scripts, which can also be run in smoke mode (`--limit N` / `smoke/*.yaml`).

```bash
bash scripts/prepare_data.sh                 # Stage 1: download, clean, tokenise, de-dup, split, vocab, streams (~1 min)
python -m pytest tests/ -q                   # 57 tests: tokeniser, causality (a), KN normalisation (b), padding (c, n-gram and neural), overfit (d), uniform
                                             # check, feature pooling/padding, incremental decoding, split integrity (split tests skip before prepare_data.sh)
bash scripts/run_part1.sh                    # Stage 2-4: KN n-gram, parameter table, smoke runs, LR probes, 9 full runs, timing, generation, tables, figures
bash scripts/run_part2.sh                    # Stage 5: word2vec, GloVe, 2 smoke + 6 frozen-embedding runs, C-scaled control (smoke + 3 runs), generation, tables, figures
bash scripts/run_part3.sh                    # Stage 6: features, classifiers (6-value C grid), 4 baselines, paired bootstrap, error exports, ablation, follow-up checks, figure, captions
```

Smoke mode (minutes, CPU or GPU): `bash scripts/prepare_data.sh --limit 500`,
`python -m src.ngram --limit 500`, `python -m src.train_lm --config configs/smoke/<model>.yaml`,
`python -m src.word2vec --limit 0.01`, `python -m src.features --config configs/smoke/part3.yaml --limit 500`,
`python -m src.classify --config configs/smoke/part3.yaml --limit 500`. Smoke outputs go to `data/smoke/`
and `results/smoke/`. `bash scripts/clean_clone_smoke.sh` clones the repository into a temporary directory
and runs every pipeline in smoke mode.

GPU selection: every script pins **one** GPU through `CUDA_VISIBLE_DEVICES` (default GPU 2;
`scripts/wait_gpu.py` waits for an idle device on this shared node). The GPU used by each run is
recorded in its log (`results/runs/<run>/log.jsonl`, record 0, `env`).

## 5. Configurations and seeds

- Common evaluation protocol (`src/evaluate.py`): blocks of L = 256 (`inputs = s[kL:kL+L]`,
  `targets = s[kL+1:kL+L+1]`, final block right-padded, pad targets excluded); every model
  conditions only on `inputs[0..j]` of the same block; neural models are stateless across blocks.
- n-gram (`configs/part1/ngram.yaml`): interpolated Kneser–Ney, orders {3, 4} × {single discount
  0.5–0.9, modified KN} chosen on LM-val → order 4, modified KN. Orders 1, 2, 5 are reference rows.
- Neural models (`configs/part1/*_seed{0,1,2}.yaml`): embedding 300 (random, trainable) → core →
  `Linear(H, 300)` projection (RNN/LSTM only) → `Linear(300, |V|)`; no weight tying. RNN: tanh,
  2 layers, H = 1072, dropout 0.3. LSTM: 2 layers, H = 512, dropout 0.3. Transformer: 4 pre-LN
  blocks, d 300, 6 heads, FFN 1200 (GELU), learned positions (256), final LayerNorm, dropout 0.1,
  causal `scaled_dot_product_attention`. Parameter counts: `results/part1/param_breakdown.csv`.
- Training (identical for every neural run): AdamW (β 0.9/0.999, weight decay 0.01 on ndim ≥ 2
  parameters), 300 warm-up steps then cosine decay to 10 % of the peak over 12 epochs,
  gradient-norm clipping 1.0, batch 64 × 256 tokens, random block offset per epoch, max 12 epochs,
  early stopping with patience 3 on LM-val, best-val checkpoint kept. Peak LR chosen per family by a
  1-epoch probe on LM-val from {3e-4, 1e-3, 2e-3} (`results/part1/lr_probes.csv`): RNN 1e-3,
  LSTM 2e-3, Transformer 2e-3. Seeds {0, 1, 2}. fp32 with TF32 matmuls; no `torch.compile`.
- Part II (`configs/part2/`): LSTM as above; B = own gensim skip-gram (300d, window 5, 10 negatives,
  5 epochs, min_count 1, seed 0, 16 workers) on the vocabulary-mapped LM-train stream, frozen;
  C = GloVe 6B 300d, frozen; missing words ~ N(0, σ_d²) with σ_d the per-dimension std of the
  covered vectors (seed 0); `<pad>` zeros; `<unk>`/`<eos>` initialised as missing words. GloVe covers
  98.76 % of the 25,000 vocabulary words, 99.945 % of the in-vocabulary LM-train word tokens and 97.935 % of
  all LM-train word positions when the 243,988 `<unk>` tokens count as uncovered
  (`results/part2/glove_coverage.json`). The whole
  input table is frozen (SHA-256 verified before/after training). Extra control (outside the main
  table): C-scaled = the GloVe table multiplied by one scalar so its mean per-dimension std equals the
  word2vec table's (`configs/part2/lstm_glovescaled_seed*.yaml`, `results/part2/ablation_glove_scaled.csv`).
- Part III (`configs/part3/classify.yaml`): IMDb train split 22,500/2,500 stratified (seed 0);
  input `<eos>` + first 255 tokens; features = 300-d pre-head vector of the seed-0 checkpoints,
  `last` or masked `mean`; `StandardScaler` + `LogisticRegression(lbfgs, max_iter 2000)`, C from
  {0.01, 0.1, 1, 10, 100, 1000} by classifier-val accuracy (ties → smaller C); IMDb test used once.
  The results of an earlier 4-value grid {0.01, 0.1, 1, 10} are kept only as `results/part3/*_Cgrid4.*`.
  Baselines with the same procedure: TF-IDF uni+bigrams (top 100k, no scaler — rows are already
  L2-normalised) and the masked means over the same inputs of three embedding tables: frozen GloVe
  (`glove_mean`), own word2vec (`w2v_mean`) and the trained input embedding of the Part I LSTM, seed 0
  (`lstmA_emb_mean`). 95 % bootstrap CIs with 1,000 resamples (seed 0); paired bootstrap of accuracy
  differences with 10,000 resamples (seed 0).
- Generation (`src/generate.py`): prompts prefixed with `<eos>`; greedy and sampling (T 0.8,
  top-k 50); exactly 60 new tokens; **`<pad>` and `<unk>` are suppressed for every model**; the
  Transformer recomputes the full prefix at every step (no KV cache).

Non-determinism: cuDNN RNN/LSTM kernels and some CUDA reductions are not bit-deterministic, so
reruns can differ in the last digits (the seed-0 probe and full-run epoch 1 agreed to 4 decimals
here); multi-worker gensim word2vec is not bit-reproducible either.

## 8. Follow-up analyses (after the main experiments)

- Part III classifier C grid extended to {0.01, 0.1, 1, 10, 100, 1000} (main table); the 4-value-grid
  results are kept as `results/part3/*_Cgrid4.*`.
- Paired bootstrap of IMDb-test accuracy differences (10,000 resamples, identical indices):
  `results/part3/paired_bootstrap.csv`.
- Extra error export chosen by design (lstm_mean vs lstm_own_mean) and two extra embedding-only
  baselines (masked mean of the word2vec table, `w2v_mean`, and of the trained Part I LSTM seed-0
  input-embedding table, `lstmA_emb_mean`) in `results/part3/results_table.csv`.
- Part II CE bucketed by the frequency of the *preceding* input token
  (`results/part2/context_freq_buckets.csv`; figure `results/figures/part2_context_freq_buckets` shows
  the difference to setting A, `part2_context_freq_buckets_abs` the absolute values).
- C-scaled control (GloVe table × one scalar so its per-dimension std equals the word2vec table's;
  frozen, 3 seeds; `configs/part2/lstm_glovescaled_seed*.yaml`), reported outside the main Part II
  table in `results/part2/ablation_glove_scaled.csv`, `stability_glove_scaled.csv` and the
  `*_with_scaled.csv` bucket tables.
- Three checks: GloVe-uncovered words in Part III inputs (`results/part3/glove_uncovered_subsets.csv`),
  truncation/borderline shares per error group (`results/part3/error_group_truncation.csv`), and
  bracket/quote closure in generations (`results/part1/generation_brackets.csv`).
- Split integrity (`src/analysis/split_checks.py`): every train/validation/test intersection is recorded in
  `results/part3/split_overlap.json`. LM splits share no text with each other or with the labelled data;
  26 classifier-val reviews have an identical, same-label copy in classifier-train. Refitting every
  classifier with those reviews (and the 14 val reviews duplicated in IMDb-test) removed from classifier-val
  leaves the chosen C unchanged for all 14 feature sets (`results/part3/val_dedup_sensitivity.csv`), so the
  overlap affects no reported test number.
- Nearest neighbours (`results/part2/nearest_neighbours.md`) compare the word2vec, GloVe and trained
  LSTM seed-0 embedding tables.

**Figures.** All figures (`results/figures/`, PDF + PNG, half-page width, no in-figure titles) use one
fixed colour-blind-safe colour, line style, marker and bar hatch per model (`src/analysis/plots.py`).
Curves over several runs show the mean with a ± std band (the three-panel `part1_learning_curves` uses a
min–max band); `part1_loss_by_position` bins positions logarithmically (per-position version:
`part1_loss_by_position_raw`); the Part II bucket figures show the difference to setting A (absolute
versions: `*_abs`); `part3_ppl_vs_accuracy` uses a broken y-axis. The plotted values of every figure are
dumped to CSV, and each figure has a one-line caption in `results/figures/CAPTIONS.md`.

## 9. Known limitations

- **Training budget**: every neural run (Part I and Part II) reached its best LM-val CE at the last
  epoch (12); the cosine schedule decays until the final epoch and the final-epoch gains (≤ 0.015 nats)
  are an order of magnitude smaller than the gaps between models, but the models were still improving.
- **Learning-rate grid**: the LSTM and Transformer optima lie at the upper edge of the pre-specified
  grid {3e-4, 1e-3, 2e-3}; larger rates were not explored. (In Part III, `transformer_mean` and the
  `lstmA_emb_mean` baseline also chose the upper edge C = 1000 of the extended C grid.)
- **Seed-0 checkpoints**: Part III features, all generations and the inference timings use the seed-0
  checkpoint of each model; only test CE/PPL and the curve/bucket figures use all three seeds.
- **Truncation**: Part III inputs are `<eos>` + the first 255 review tokens (34.7 % of IMDb-test and
  36.2 % of IMDb-train reviews are truncated); the last-255 ablation shows this matters.
- **Numerical reproducibility**: lbfgs refits are not bit-reproducible (multi-threaded BLAS), so
  identical C settings can differ in the 4th decimal between runs; cuDNN RNN kernels and gensim
  multi-worker training are not bit-deterministic either.
- **Classifier-val duplicates**: IMDb-train contains 98 duplicate reviews, and the stratified
  classifier split is not group-disjoint, so 26 classifier-val reviews also occur in classifier-train.
  This does not change any chosen C (§8), but classifier-val accuracies are slightly optimistic.
- **Single dataset**: all language models, embeddings and classifiers use IMDb only (unsupervised
  split for the LMs, labelled splits for Part III); GloVe is the only external data.
- **Setting A reuse**: in the Part II generation and bracket/quote tables, A is the very same checkpoint
  as the Part I LSTM seed 0 (as the specification prescribes, `docs/TASK.md` §5), so those rows
  duplicate the Part I LSTM rows.

## 11. Attribution

All code in `src/` was written for this assignment. Design conventions follow public references:
the GPT-2 initialisation scheme (normal(0, 0.02), residual projections scaled by 1/√(2L)) as used
in nanoGPT (Karpathy); the modified Kneser–Ney discount estimates of Chen & Goodman (1998) with the
KenLM fallback discounts (Heafield et al., 2013); the PyTorch word-language-model example's
uniform(−0.1, 0.1) embedding initialisation for the recurrent models. Data: Maas et al. (2011),
*Learning Word Vectors for Sentiment Analysis*. Embeddings: Pennington, Socher & Manning (2014),
*GloVe: Global Vectors for Word Representation*; Mikolov et al. (2013) via gensim (Řehůřek & Sojka).
